# Patterns

One note per named pattern, written **after** you meet it in a real problem — never in
advance. A pattern note you wrote from a tutorial is inert; one you wrote the moment a
problem clicked is retrievable under interview pressure.

Each note should answer four things and nothing else:

1. **Trigger** — what in the problem statement tells you this is the one. This is the
   only part that matters in an interview.
2. **Shape** — the skeleton, in 5–10 lines of pseudocode.
3. **Complexity** — time and space, and *why*.
4. **Failure modes** — where it breaks, and the variant that looks identical but isn't.
